## 快速开始

### 1. 编译固件

必须用 **STM32CubeIDE**（Keil 无法链接 NanoEdge 的静态库，相关工程已删除）。
不开图形界面也能编：

```powershell
$tc = 'E:\WORK\STM32CubeIDE_2.1.1\STM32CubeIDE\plugins\com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.14.3.rel1.win32_1.0.100.202602081740\tools\bin'
$mk = 'E:\WORK\STM32CubeIDE_2.1.1\STM32CubeIDE\plugins\com.st.stm32cube.ide.mcu.externaltools.make.win32_2.2.100.202601091506\tools\bin'
$env:PATH = "$tc;$mk;$env:PATH"
make.exe -C Debug -j8 all
```

产物：`Debug/BOAT.elf`（约 107 KB text）。

> 换机器时，用 CubeIDE 打开本目录重新 Build 一次即可重新生成 `Debug/` 下的 makefile。

### 2. 启动 WebUI

```bash
cd WebUI
npm install     # 首次
npm start       # http://localhost:3000
```

Windows 上也可以直接双击 `WebUI/run-webui.bat`（会自动检查端口占用）。

### 3. 一条命令自检

```bash
node tools/boatctl/bin/boatctl.js selftest --open COM7 --out report.json
```

会自动连串口、采一段数据、按 8 项判据给出通过/警告/失败，退出码可直接用于脚本。
详见 [`tools/boatctl/README.md`](tools/boatctl/README.md)。

## 通信协议

### 上行：STM32 → WebUI（每行一条 JSON，`\r\n` 结尾，**2 秒一次**）

> **为什么是 2 秒而不是 1 秒：LoRa 是半双工共享信道。**
> 上行遥测占掉空口，下行命令就挤不进去。实测（90 字节下行报文，各测 3 次）：
>
> | 遥测周期 | 下行成功率 |
> |---|---|
> | **1000ms** | **0/3** ← 空口被占满，命令完全发不进去 |
> | 1500ms | 3/3 |
> | 2000ms | 3/3 |
> | 3000ms | 3/3 |
>
> 这正是"导航指令从来发不到船上"的根本原因。默认取 2000ms 留有余量；
> 需要更快的界面刷新可以用 `T<毫秒>` 指令现场调（`T1000` 会让下行失效）。

```json
{"t":"boot","v":1,"ms":123,"msg":"boat telemetry start","phdiv":100,"tbdiv":150}
{"t":"data","v":1,"seq":0,"ms":1234,"ph":717,"phr":412,"phmv":1640,
 "tc":2538,"tv":1,"fix":1,"sat":12,"lat":345001000,"lon":1040001000,
 "iv":1,"ir":12,"ip":-34,"iy":9012,"ib":2048,"ia":128,"gb":76438,"gl":1228,
 "ns":1,"nd":350,"nt":-123,"bs":1,"bd":350,"rs":0,"rd":0,"xt":-20,"ch":90,
 "aiph":91,"aiphn":1,"ait":87,"aitn":1,"mls":100,"mrs":85,"mlo":0,"mro":10}
```

| 字段 | 含义 | 缩放 |
|---|---|---|
| `ph` / `phr` / `phmv` | pH 值 / ADC 原始值 / ADC 电压 mV | ×100 / raw / raw |
| `tc` / `tv` | 水温 / 有效标志 | ℃×100 / 0-1 |
| `fix` / `sat` / `lat` / `lon` | GPS 定位状态 / 卫星数 / 经纬度 | - / - / ×1e7 |
| `iv` / `ir`/`ip`/`iy` | IMU 有效 / Roll/Pitch/Yaw | - / 度×100 |
| `ib` / `ia` | IMU 接收字节 / 姿态帧数 | raw |
| `gb` / `gl` | GPS 接收字节 / NMEA 行数 | raw |
| `ns` / `nd` / `nt` | 导航状态 / 到目标距离 / 航向误差 | - / m×100 / 度×100 |
| `bs` / `bd` | 边界状态 / 距边界距离（负数=越界） | - / m×100 |
| `rs` / `rd` | 归位状态 / 距归位点距离 | - / m×100 |
| `xt` / `ch` | 横向偏差 / 横向修正后目标航向 | m×100 / 度×100 |
| `to` / `lw` / `rw` | 转向输出(内环 PID) / 左右电机实际 PWM | -999~999 |
| `hk`/`hi`/`hd` | 当前生效的内环增益（航向 kp/ki/kd） | ×1000 |
| `xk`/`xi`/`xd` | 当前生效的外环增益（横向 kp/ki/kd） | ×1000 |
| `aiph`/`aiphn`/`ait`/`aitn` | 边缘 AI：pH 相似度/是否正常、温度相似度/是否正常 | 0-100 / 0-1 |
| `mls`/`mrs`/`mlo`/`mro` | 电机校准：左右缩放(×100)、左右偏移 | - |
| `mlz`/`mrz` | 左右电机启动死区补偿（PWM counts） | - |

导航状态 `ns`：0 待机 / 1 导航中 / 2 区域保持 / 3 GPS 丢失 / 4 越界归位。

### 下行：WebUI → STM32

```json
{"t":"target","zone":"zone_A","lat":345001000,"lon":1040001000,
 "r":5,"ar":1,"rr":8,"bm":2,
 "bclat":345001000,"bclon":1040001000,"blen":20,"bwid":10}
{"t":"cmd","cmd":"stop"}      // stop / start / sensor / dtest
{"t":"motor","l":50,"r":50}   // -100 ~ 100
{"t":"mcal","ls":1.0,"rs":0.85,"lo":0,"ro":10,"ldz":80,"rdz":65}
{"t":"pid","hkp":2.0,"hki":0.35,"hkd":0.25,"xkp":2.3,"xki":0.30,"xkd":0.12}
```

**紧凑文本指令**（长度压到 20 字节以内，链路差时更可靠）：

| 指令 | 含义 |
|---|---|
| `G<纬度×1e6>,<经度×1e6>` | 设置目标点，如 `G34500100,10400010` |
| `P<hkp×1000>,<hki×1000>,<hkd×1000>` | 设置航向 PID，横向增益保持不变 |
| `T<毫秒>` | 设置遥测周期（默认 2000） |
| `Q` / `L` | 静音（8 秒一次）/ 恢复正常周期 |

船端收到任何命令都会回 `{"t":"ack","kind":...}`。**判断命令是否送达要看 ack，
不能只看串口写入成功**——那只能说明字节写进了 PC 的串口。

`pid` 用于**运行时整定**，无需重新编译烧录；省略的字段保持原值。
修改后积分/微分状态会清零，避免换参数瞬间的冲击。

`mcal` 的 `ldz`/`rdz` 是左右电机**启动死区补偿**（PWM counts，0=不补偿），
省略则保持当前值。死区补偿会把指令 1~100 线性映射到 `deadzone~999`，
解决"小指令不转、一过阈值就猛冲"。**calibration 的 offset 现在只在非零指令时生效**，
修掉了原先 speed=0 仍有 PWM 输出导致船慢慢蠕动的问题。

`ar` 到达半径、`r` 保持半径、`rr` 漂移归位半径、`bm` 边界容差（米）。
`bclat/bclon/blen/bwid` 为区域矩形，用于越界判定与归位。

## 区域保持（巡检模式的核心）

到达目标后进入 `nav.state = NAV_HOLDING`（遥测 `ns=2`）。

**语义是"守一个区域"，不是"钉在一个点上"。** GPS 静差本身就有 2~5 米，
守点只会在噪声里来回抖、电机疯狂启停，而且永远不可能真的停住。

保留半径取 `r`（默认 6 m），收敛目标是它的一半：

| 误差 = 距离 − r×0.5 | 行为 |
|---|---|
| < 0.5 m | 停桨 |
| > 1.5 m | 开始修正（迟滞区间，防抖） |
| 修正中 | 油门 = 18 + 4.0×误差 + 积分项，上限 80 |

积分项是必需的：**纯 P 控制在恒定水流下必然有稳态偏差**——船会停在
"推力刚好等于水流"的距离上。强流时这个距离会顶到 6~7 米，直接压到后端
6 米的任务暂停线上。加积分后偏差被消掉。

### 为什么不守点

上一版把死区做成到达半径（2 m），结果是**在 GPS 噪声里持续修正**：
仿真里电机每秒启停 8~20 次。改成"区域 + 迟滞 + PI"之后：

| 水流 | 稳态均值 | 最远 | 越过 6 m 暂停线 | 电机启停(180 s) |
|---|---|---|---|---|
| 0.35 m/s | 4.0 m | 4.5 m | 0% | 45 |
| 0.15 m/s | 4.0 m | 4.5 m | 0% | 44 |
| 静止 | 3.5 m | 3.5 m | 0% | 2 |

启停约 4 秒一次，真机有惯性不会啸叫；且**任何水流下都不会越过 6 米暂停线**。

### 旧实现的问题（供参考）

```c
if (distance > drift_radius)   // 8 m
    朝目标开一下;
else
    电机全停;
```

- 死区就是 8 米，8 米内完全不管 —— 漂流瓶
- 只在 >8 m 时动、一进 8 m 就停，**平衡点永远落在 8 米边界上**，回不到目标
- 修正油门 30 只对应约 0.18 m/s，比常见风漂还小，强流下会被一直冲走（仿真 40 m）

> 实际保持精度受 GPS 静差限制，大约 3~5 米。想更准需要 RTK/差分，
> 不是调 PID 能解决的。

## 已知限制

1. **导航闭环尚未实水验证。** 代码路径已用台架注入跑完整 8 点巡检，但真实水面的 PID 表现需要上水标定。
   增益可用 `{"t":"pid",...}` 运行时下发，配合 `navrun` / `pidreport` 按数据调参。
2. **pH 未标定。** `ph` 是估算值，只有 `phr`/`phmv` 可信。用两点法（白醋 ≈ pH3、小苏打水 ≈ pH8）重算斜率截距。
3. **前端图标依赖 CDN**（unpkg 的 lucide），离线环境下图标会全部消失。
4. **端侧 AI 的"正常"参考与部署水体不一致。** 模型本身工作正常
   （遥测 `api/apd/ati/atd` 全为 0 = 初始化与推理都成功），问题在训练标签：

   | 训练数据 | 取值 |
   |---|---|
   | pH 正常样本 | `ph=9.28`（ph_raw≈6286, mV≈1266） |
   | pH 异常样本 | `ph=6.76`（ph_raw≈8506, mV≈1713） |
   | 温度正常样本 | 23.5℃ |

   而探头现在泡在保护液/清水里，实测 `ph≈7.5`、`22.9℃`——落在"异常"那一侧，
   所以相似度 pH=0、温度=52（阈值 80），被判为异常。**模型是在如实报告
   "这和我的正常参考不一样"，不是故障。**

   因此 AI 判定默认不参与风险（`BOAT_AI_GATE=1` 开启）。要用的话必须用**鱼塘实际水体**
   采一批 normal 样本重新训练，让"正常"等于正常养殖水而不是 pH 9.28 的标液。
5. **电机 PWM 死区尚未实测标定。** 映射本身已在架空状态验证
   （`0→0`、`10→99`、`50→499`，符合 `|cmd|×999/100`），零指令归零也已确认。
   但左右电机的起转阈值还没测，死区补偿默认 0（=原行为），需通过 `mcal` 的 `ldz`/`rdz` 写入。
6. **LoRa 下行会丢字节，长报文不可用。** 实测超过约 40 字节开始丢字节、报文被截断；
   147 字节的 `target` 重发 8 次全部失败。已提供紧凑文本指令 `G<lat×1e6>,<lon×1e6>`
   与 `P<hkp>,<hki>,<hkd>`（20 字节以内，实测 3/3 送达）。完整 JSON 仍保留但需重试。
