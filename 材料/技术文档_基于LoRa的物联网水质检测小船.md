# 基于LoRa的物联网水质检测小船 · 技术文档

**作品名称**：基于LoRa的物联网水质检测小船（智航清泓）

---

## 摘要

本项目设计并实现了一款面向水产养殖场景的小型无人船水质监测系统。系统以 STM32U5A5ZJTxQ 微控制器为核心，搭载 pH 传感器、浊度传感器、DS18B20 温度传感器以及 GPS/IMU 模块，通过 LoRa 无线通信将水质数据实时回传至本地 PC。本地 PC 运行 Node.js 后端服务（Express + WebSocket + SerialPort），通过 USB 串口接收 LoRa 数据，浏览器 WebUI 提供三栏式实时监控界面，包含 Leaflet 地图、区域卡片和控制面板。

系统支持养殖区域管理（矩形区域 + 养殖品种配置）、GPS+IMU 航点导航（PID 航向控制）、多点自动巡检采样（每区域 8 点）、边缘 AI 传感器健康检测（NanoEdge AI Studio 训练模型运行在 STM32 上）、大模型风险分析（DeepSeek/Anthropic 云端 API + Ollama 本地模型 + 规则兜底）以及电机校准系统。数据以 JSON 文件本地存储，无需云服务器或 MQTT 中间件。

本项目参加全国大学生嵌入式芯片与系统设计竞赛 · 意法半导体赛道 · 选题六 IoT。

## 第一部分　作品概述

### 1.1 功能与特性

本系统具备以下核心功能与特性：

1. **多参数水质实时采集**：小船搭载 pH 传感器（ADC 直连）、浊度传感器（ADC + 2/3 分压）和 DS18B20 数字温度传感器，可同步采集水域三项关键水质指标。STM32 主循环每 20ms 执行一次，遥测数据以 JSON 格式通过 LoRa 每秒上报一次。

2. **GPS+IMU 航点导航**：集成 ATK-MO1218 GPS 模块（UART4, 38400 baud）和 ATK-IMU901 九轴姿态传感器（USART2, 115200 baud），实现基于 PID 航向控制的自主导航。到达目标 5m 范围内判定为到达，8m 偏移触发漂移修正。

3. **养殖区域管理与多点巡检**：支持创建矩形水产养殖区域，每个区域独立配置养殖品种（草鱼、鲫鱼、鲤鱼、鲈鱼、虾、蟹等）和水质阈值。启动巡检后自动生成 8 个采样点（4 角 + 4 边中点），依次导航前往、稳定 30 秒后采样。

4. **LoRa 远距离无线传输**：采用 LoRa 无线通信模块，通过 USART3（PB10/PB11, 115200 baud）与 STM32 连接，将水质数据远距离传输至 USB 串口接收端，适合水域场景的无线数据回传。

5. **浏览器 WebUI 实时监控**：三栏式 Dashboard 界面——左侧深色遥测面板（传感器原始值、GPS/IMU 状态、导航信息、电机校准值）、中间 Leaflet 地图 + 区域卡片网格、右侧控制面板（快捷指令、电机测试/校准、导航监视器）。高级模式可展开调试信息。

6. **边缘 AI 传感器健康检测**：在 STM32 上部署 NanoEdge AI Studio 训练的异常检测模型（pH 5 维输入、温度 3 维输入），实时判断传感器工作状态是否正常，结果通过 LoRa 遥测字段（`aiph/aiphn/ait/aitn`）回传，供后端风险分析参考。

7. **大模型风险分析**：支持云端 API（DeepSeek、Anthropic 兼容接口）和本地 Ollama 模型两种 LLM 后端，不可用时自动降级为规则引擎（按阈值判断 normal/warning/danger）。风险分析提示词中整合了边缘 AI 传感器健康状态。

8. **电机校准系统**：TB6612 双 H 桥驱动两个推进电机，通过 WebUI 可为每个电机独立设置缩放系数和偏移量，补偿物理转速差异和死区。

### 1.2 应用领域

本系统主要面向以下应用领域：

1. **水产养殖水质管控**：适用于各类淡水养殖池塘、虾蟹养殖塘等，实时监测水体 pH 值、浊度和温度，帮助养殖户精准掌握各养殖区域的水质状况，及时发现风险。

2. **城郊小型湖泊生态监测**：可用于城市周边景观湖泊、人工湿地等小型水体的水质监测，提供连续的水质数据。

3. **农村灌溉水塘监测**：适用于农业灌溉蓄水塘的水质检测，确保灌溉用水安全。

4. **河道浅水域巡查**：可用于中小型河道、溪流等浅水区域的水质巡检，替代传统人工采样方式。

整套系统基于本机部署，成本低、无需云服务，特别适合预算有限的基层水产养殖场景。

### 1.3 主要技术特点

1. **低功耗主控设计**：采用 STM32U5A5ZJTxQ 微控制器，基于 Arm Cortex-M33 内核，主频最高 160MHz，集成 512KB Flash 和 256KB SRAM，支持多种低功耗模式。

2. **本地化全栈架构**：STM32 → LoRa → USB 串口 → Node.js 后端 → 浏览器 WebUI，数据链路全在本地，无需云服务器、MQTT 中间件或公网部署，降低了系统复杂度和运行成本。

3. **GPS+IMU 融合导航**：GPS 提供绝对位置，IMU 提供航向参考，PID 控制器实时修正航向偏差，实现可靠的航点导航和区域保持。

4. **边缘 AI + 云端 LLM 协同**：STM32 端运行 NanoEdge AI 异常检测模型判断传感器健康状态，云端/本地 LLM 结合传感器数据和边缘 AI 结果进行综合风险评估，兼顾实时性和智能分析深度。

5. **裸机固件架构**：STM32 固件采用裸机（bare-metal）HAL 库开发，主循环 20ms 周期，50ms 更新导航，1000ms 发送遥测 JSON，任务简单明确、可预测性好。

### 1.4 主要性能指标

| 性能指标 | 参数值 | 说明 |
|---|---|---|
| pH 值 | 范围 0~14 | 公式为估算值，需标准液校准；原始 ADC 值准确 |
| 浊度 | 范围 0~3000 NTU | 公式为估算值；原始 ADC 值准确 |
| 水温 | ±0.5°C（DS18B20） | 数字传感器，精度有保障 |
| GPS 定位 | 需室外测试验证 | 室内 fix=0 为正常现象 |
| IMU 姿态 | Roll/Pitch/Yaw | ATK-IMU901 九轴，ATKP 协议解析 |
| LoRa 通信 | 115200 baud | 距离取决于环境，水面对信号有反射影响 |
| 数据上报周期 | 约 1000ms（1s） | JSON 格式，`\\r\\n` 结尾 |
| 导航精度 | 5m 到达半径，8m 漂移修正 | PID 航向控制 |
| ADC 分辨率 | 14-bit | 3.3V 参考，采样时间 391.5 周期 |

> **诚实说明**：pH 和浊度的物理量换算公式基于估算，未经标准液标定校准。但原始 ADC 读数和 mV 电压值是准确的，可用于判断传感器是否正常工作和相对变化趋势。GPS 模块需在室外环境下验证定位功能。

### 1.5 主要创新点

1. **自主巡航+水质检测+区域管理一体化**：不仅实现无人船自主巡航和多参数水质检测，还集成了养殖区域管理、品种配置、多点自动巡检采样的完整产品闭环，面向真实水产养殖场景。

2. **边缘 AI 传感器健康检测**：利用 NanoEdge AI Studio 在 STM32 上部署异常检测模型，实时判断 pH 和温度传感器的工作状态，为上层风险分析提供数据可信度参考，是嵌入式端侧智能的典型应用。

3. **边缘 AI + LLM 两级智能分析**：STM32 端做传感器健康检测（实时、低延迟），云端/本地 LLM 做综合风险评估（语义分析、养殖建议），两级协同既有嵌入式含量又有产品深度。

4. **本机全栈部署**：STM32 → LoRa → 本机 Node.js → 浏览器，无需云服务器和 MQTT 中间件，数据全在本地，部署简单、运行成本为零。

5. **电机校准系统**：针对两个推进电机物理特性差异，提供 WebUI 可调的 per-motor 缩放/偏移校准，无需修改固件代码。

### 1.6 设计流程

本项目设计流程如下：首先进行需求分析，面向水产养殖户的核心需求——了解各区域水质状况、是否有风险、是否需要派船采样；然后进行系统总体方案设计，确定 STM32 + LoRa + 本机 WebUI 的技术路线；接着开展硬件设计，包括传感器选型、TB6612 电机驱动、GPS/IMU 模块集成及自定义 PCB 设计；同步进行软件设计，涵盖 STM32 裸机固件（Keil MDK-ARM）、Node.js 后端和浏览器前端；之后进行 PCB 制板、焊接与逐模块调试；最后在实际水域场景中进行集成测试。

## 第二部分　系统组成及功能说明

### 2.1 整体介绍

本系统采用 STM32 → LoRa → 本机 PC → 浏览器 的四段式架构：

```
STM32U5 传感器/电机控制板
  │
  ├─ pH 传感器 (PC0, ADC)
  ├─ 浊度传感器 (PC1, ADC + PB0, 数字)
  ├─ DS18B20 温度 (PB1, 单总线)
  ├─ GPS (UART4, PA0/PA1, 38400)
  ├─ IMU901 (USART2, PA2/PA3, 115200)
  ├─ TB6612 电机驱动 (TIM1 CH1/CH2, PE9/PE11)
  └─ NanoEdge AI (pH/温度异常检测)
  │
  ↓ LoRa (USART3, PB10/PB11, 115200)
  │
USB 串口接收端（插在本地 PC）
  │
  ↓ SerialPort 库
  │
Node.js 后端 (server.js)
  ├─ Express HTTP 服务
  ├─ WebSocket 实时推送
  ├─ 区域管理 (zones.json)
  ├─ 采样状态机 + 存储 (samples.jsonl)
  ├─ LLM 风险分析 (DeepSeek/Ollama/规则兜底)
  └─ 下行命令转发
  │
  ↓ WebSocket
  │
浏览器 WebUI (http://localhost:3000)
  ├─ 左栏：实时遥测面板
  ├─ 中栏：Leaflet 地图 + 区域卡片
  └─ 右栏：控制面板（指令/电机/校准/导航/区域详情）
```

各段之间通过标准化接口通信：STM32 与外设之间通过 UART/ADC/GPIO，STM32 与 LoRa 之间通过 USART3，Node.js 通过 SerialPort 库读取 USB 串口，浏览器与 Node.js 之间通过 WebSocket 实时通信。

> **说明**：微信小程序作为移动端扩展方案已完成初步开发，但在当前演示版本中暂不使用，不依赖公网服务器。

### 2.2 硬件系统介绍

#### 2.2.1 硬件整体介绍

本系统硬件部分主要包括以下核心模块：

1. **主控模块**：采用 STM32U5A5ZJTxQ 微控制器，基于 Arm Cortex-M33 内核，主频最高 160MHz，集成 512KB Flash 和 256KB SRAM，提供丰富的 GPIO、ADC、UART、SPI、I2C 等外设接口。

2. **传感器模块**：
   - **pH 传感器**：玻璃电极法，模拟输出直接连接至 STM32 的 ADC1_IN1（PC0），PCB 新版直连不分压，14-bit ADC 采样。
   - **浊度传感器**：光散射原理，模拟输出经 2/3 分压后连接至 ADC1_IN2（PC1），另有数字输出连接 PB0（GPIO 输入，带上拉），14-bit ADC 采样。
   - **DS18B20 温度传感器**：数字温度传感器，单总线协议连接 PB1，需 4.7kΩ 上拉电阻至 3.3V，精度 ±0.5°C。

3. **定位与姿态模块**：
   - **GPS**：ATK-MO1218 模块，UART4 接口（PA0/PA1），38400 baud，NMEA 协议解析。
   - **IMU**：正点原子 ATK-IMU901 九轴姿态传感器，USART2 接口（PA2/PA3），115200 baud，ATKP 协议解析，提供 Roll/Pitch/Yaw。

4. **通信模块**：LoRa 无线通信模块，通过 USART3（PB10/PB11）与主控连接，115200 baud，将 JSON 遥测数据无线传输至 USB 串口接收端。

5. **电机驱动模块**：TB6612 双 H 桥电机驱动芯片，驱动两个推进直流电机。TIM1 CH1（PE9）和 TIM1 CH2（PE11）输出 PWM 控制转速，PC8/PC9 控制左电机方向，PC10/PC11 控制右电机方向，PD4 为使能引脚（STBY）。

6. **电源模块**：可充电锂电池供电，配合 DC-DC 变换器为各模块提供稳定的 3.3V 和 5V 电源。

#### 2.2.2 PCB 设计介绍

硬件采用自定义双层 PCB 设计，替代了早期的面包板飞线方案。PCB 集成了所有传感器接口、电机驱动、LoRa 通信和电源管理电路，布局紧凑可靠。

PCB 关键设计要点：
- pH 传感器直连 ADC（不分压），简化了模拟前端电路
- 浊度传感器采用 2/3 分压（电阻分压网络），保护 ADC 输入
- TB6612 电机驱动电路集成在板上，PWM + 方向信号直接连接 STM32
- 各模块电源去耦，LoRa 模块增加大容量储能电容应对发射瞬时电流
- SWD 调试接口（PA13/PA14）保留用于固件烧录

#### 2.2.3 电路各模块介绍

**引脚连接总表**：

| 模块 | STM32 引脚 | 功能 | 说明 |
|---|---|---|---|
| TB6612 PWMA | PE9 | TIM1_CH1 PWM | 左电机 PWM |
| TB6612 AIN1/AIN2 | PC8/PC9 | GPIO_Output | 左电机方向 |
| TB6612 PWMB | PE11 | TIM1_CH2 PWM | 右电机 PWM |
| TB6612 BIN1/BIN2 | PC10/PC11 | GPIO_Output | 右电机方向 |
| TB6612 STBY | PD4 | GPIO_Output | 使能（默认高） |
| LoRa TX/RX | PB10/PB11 | USART3 | 115200 baud |
| GPS TX/RX | PA0/PA1 | UART4 | 38400 baud |
| IMU901 TX/RX | PA2/PA3 | USART2 | 115200 baud |
| pH 模拟 | PC0 | ADC1_IN1 | 直连不分压 |
| 浊度模拟 | PC1 | ADC1_IN2 | 2/3 分压 |
| 浊度数字 | PB0 | GPIO_Input | 数字输出（带上拉） |
| DS18B20 | PB1 | GPIO | 单总线，需 4.7kΩ 上拉 |
| 调试 SWD | PA13/PA14 | SWDIO/SWCLK | 固件烧录 |

**方向控制逻辑**：AIN1=高、AIN2=低 正转；AIN1=低、AIN2=高 反转。BIN 同理。

**ADC 配置**：14-bit 分辨率，3.3V 参考电压，采样时间 391.5 周期。

### 2.3 软件系统介绍

#### 2.3.1 软件整体介绍

软件系统分为嵌入式固件和上位机软件两大部分：

**嵌入式固件**：基于 STM32CubeMX 生成的 HAL 库工程，采用 Keil MDK-ARM 工具链开发，裸机（bare-metal）架构，主循环 20ms 周期。主要包含传感器数据采集、LoRa 遥测发送、下行命令解析、PID 航向导航和 NanoEdge AI 异常检测等功能模块。

**Node.js 后端**：单文件 `server.js`，基于 Express + WebSocket + SerialPort 库构建。通过 USB 串口读取 LoRa 数据，解析 JSON 遥测帧，通过 WebSocket 实时推送至浏览器。实现区域管理、采样状态机、LLM 风险分析、下行命令转发等功能。数据以 JSON 文件本地存储（`data/zones.json` + `data/samples.jsonl`）。

**浏览器前端**：HTML + CSS + JavaScript，三栏式 Dashboard 布局，使用 Leaflet 地图库。无需构建工具，直接由 Express 静态文件服务。

#### 2.3.2 嵌入式固件模块介绍

| 源文件 | 功能 |
|---|---|
| `Core/Src/main.c` | 主循环：初始化、20ms 周期调度、遥测发送（1000ms）、下行命令处理、导航更新（50ms） |
| `Hardware/Lora.c` | LoRa 收发，JSON 解析下行命令（target/cmd/motor/mcal） |
| `Hardware/Navigation.c` | PID 航向控制、大圆距离/航向计算、导航状态机（空闲→导航→区域保持→GPS 丢失） |
| `Hardware/Motor.c` | TB6612 电机驱动 + per-motor 缩放/偏移校准 |
| `Hardware/GPS.c` | NMEA 协议解析（GPGGA/GPRMC 等） |
| `Hardware/IMU901.c` | 正点原子 ATK-IMU901 ATKP 协议姿态解析 |
| `Hardware/PH.c` | pH ADC 读取、电压换算、pH 值计算 |
| `Hardware/Turbidity.c` | 浊度 ADC 读取、2/3 分压还原、NTU 计算、数字输出读取 |
| `Hardware/DS18B20.c` | DS18B20 单总线温度读取（修正了 85°C 默认值问题） |
| `Hardware/EdgeAI.c` | NanoEdge AI 异常检测封装（pH 5 维 + 温度 3 维） |

**主循环时序**：
- 20ms：基础循环周期，处理串口接收、命令解析
- 50ms：导航状态更新，PID 航向控制输出电机 PWM
- 1000ms：组装 JSON 遥测帧，通过 LoRa 发送

**遥测 JSON 格式**（每行以 `\\r\\n` 结尾）：

```json
{
  "t": "data", "v": 1, "seq": 0, "ms": 1234,
  "ph": 717, "phr": 412, "phmv": 1640,
  "tb": 2860, "tbr": 730, "tbmv": 2940, "td": 1, "tbv": 1,
  "tc": 2538, "tv": 1,
  "fix": 0, "sat": 0, "lat": 0, "lon": 0,
  "iv": 1, "ir": 12, "ip": -34, "iy": 9012,
  "ns": 1, "nd": 350, "nt": -123,
  "mls": 100, "mrs": 85, "mlo": 0, "mro": 10,
  "aiph": 91, "aiphn": 1, "ait": 87, "aitn": 1
}
```

**下行命令格式**：

| 命令 | 格式 | 固件行为 |
|---|---|---|
| target | `{"t":"target","zone":"zone_A","lat":345001000,"lon":1040001000,"r":5}` | 设置导航目标，启动导航 |
| cmd stop | `{"t":"cmd","cmd":"stop"}` | 停止导航 + 电机 |
| cmd start | `{"t":"cmd","cmd":"start"}` | 回 ack |
| cmd sensor | `{"t":"cmd","cmd":"sensor"}` | 立即发送一次遥测数据 |
| motor | `{"t":"motor","l":50,"r":50}` | 直接设置左右电机 PWM（-100~100） |
| mcal | `{"t":"mcal","ls":1.0,"rs":0.85,"lo":0,"ro":10}` | 设置电机校准系数（缩放 0.1~2.0，偏移 -200~200） |

#### 2.3.3 Node.js 后端模块介绍

`后端/webui/webui/server.js` 是单文件 Node.js 服务，功能模块如下：

1. **串口通信**：通过 SerialPort 库连接 USB 串口（115200 baud），按 `\\r\\n` 拆行解析 JSON 遥测帧，通过 WebSocket 实时推送至浏览器。

2. **区域管理**：维护 `data/zones.json`，每个区域包含 ID、名称、养殖品种配置（含 pH/温度/浊度阈值）、矩形几何信息（中心点 + 南北/东西尺寸）。

3. **采样状态机**：用户选择区域并发送目标后，自动按矩形生成 8 个采样点，依次导航前往每个点，到达后稳定 30 秒、每 5 秒保存一条样本至 `data/samples.jsonl`。支持漂移检测（离开 5m 暂停告警）和超时处理（10 分钟未到 5m 暂停告警）。

4. **LLM 风险分析**：支持多种 LLM 后端——云端 API（DeepSeek、Anthropic 兼容接口）、本地 Ollama 模型。LLM 不可用时自动降级为规则引擎。分析提示词中整合了边缘 AI 传感器健康状态，不同养殖品种使用不同阈值。结果缓存 5 分钟。

5. **下行命令转发**：WebUI 发送的控制指令通过串口转发至 STM32，支持手动发送 JSON 和预设按钮（停船/启动/传感器/电机测试/校准）。

6. **本地数据存储**：
   - `data/zones.json`：区域配置持久化
   - `data/samples.jsonl`：采样历史，每行一条 JSON

启动方式：

```bash
cd 后端/webui/webui
npm install
npm start
# 浏览器访问 http://localhost:3000
```

#### 2.3.4 浏览器前端介绍

前端采用 HTML + CSS + JavaScript 构建，使用 Leaflet 地图库，三栏式布局：

- **左栏（深色遥测面板）**：实时显示串口连接状态、pH/浊度/温度传感器数据（含 raw ADC 和 mV 电压）、GPS 状态（定位/卫星数/经纬度/接收字节数）、IMU 姿态（Roll/Pitch/Yaw）、导航状态（状态/距离/航向误差）、序列号/uptime、电机校准值、边缘 AI 状态，可折叠原始 JSON。

- **中栏**：Leaflet 地图始终显示，矩形色块标注各养殖区域，点击地图可选点发送导航目标。下方区域卡片网格展示各区域的 pH/水温/浊度和风险状态。

- **右栏**：快捷指令（停船/启动/传感器）、电机测试（左右滑块 + 前进/后退/左转/右转预设）、电机校准（缩放滑块 + 偏移输入）、导航监视器（大字状态/距离/航向误差）、区域详情（风险分析 + 操作按钮）。

- **设置齿轮 ⚙**：串口连接管理、手动指令发送、采样参数配置、LLM 后端配置、区域管理（新增/编辑/删除）、采样历史查看、通信日志。

- **高级模式**：右上角开关，控制调试信息的显示/隐藏。

#### 2.3.5 NanoEdge AI 边缘智能

本项目集成了两个 NanoEdge AI Studio 训练的异常检测模型：

| 模型 | 输入维度 | 输入字段 | 固件库文件 |
|---|---|---|---|
| pH 传感器健康检测 | 5 | ph_raw, ph_mv, ph, ph_delta, ph_mv_delta | `AI/ph/libneai_ph.a` |
| 温度传感器健康检测 | 3 | temperature, temperature_valid, temperature_delta | `AI/temperature/libneai_temperature.a` |

由于 NanoEdge AI 为每个模型生成的默认 API 符号名称相同，本项目将两套符号分别加前缀（`ph_neai_*` 和 `temperature_neai_*`）以避免链接冲突。固件通过 `Hardware/EdgeAI.c` 封装层调用，对 `main.c` 暴露 `EdgeAI_Init()`、`EdgeAI_UpdatePh()`、`EdgeAI_UpdateTemperature()` 和 `EdgeAI_GetStatus()` 接口。

模型输出 similarity 分数（0-100），高于阈值（默认 80）判定为正常。结果通过 LoRa 遥测的 `aiph/aiphn/ait/aitn` 字段回传，后端风险分析可参考这些传感器健康状态。

## 第四部分　总结

### 4.1 可扩展之处

本系统在后续开发中可从以下几个方面进行扩展和优化：

1. **增加更多水质参数**：集成溶解氧（DO）、电导率（EC）、氨氮等传感器，实现更全面的水质监测。STM32U5 的 ADC 通道和 UART 接口仍有余量。

2. **传感器标定校准**：使用标准液对 pH 和浊度传感器进行系统标定，建立准确的 ADC 值-物理量映射关系，替换当前的估算公式。

3. **太阳能充电**：增加太阳能充电模块，提升小船续航能力，实现长期无人值守的持续监测。

4. **多船协同**：扩展 LoRa 协议支持多艘小船组网，实现更大水域的分区协同监测。

5. **微信小程序对接**：当前微信小程序前端已完成初步开发，后续可接入公网服务器，实现移动端远程查看。

6. **NanoEdge AI 扩展**：当前仅部署了传感器健康检测模型，可进一步训练水质趋势预测和异常分类模型，提升边缘智能分析能力。

7. **自动避障**：集成超声波或激光雷达传感器，结合 IMU 数据实现障碍物检测和自动避障。

8. **数据可视化增强**：增加时间序列趋势图表、水质变化热力图等高级可视化功能。

### 4.2 心得体会

在本项目的设计与实现过程中，我们团队收获了许多宝贵的经验和教训。

**硬件方面**：PCB 设计中电源管理至关重要。LoRa 模块发射时的瞬时大电流需求、电机启停对电源的干扰，都需要在 PCB 布局中充分考虑。pH 和浊度传感器的模拟前端设计也是挑战——pH 电极输出信号微弱且内阻高，浊度传感器需要合理的分压网络保护 ADC。从面包板飞线到自定义 PCB 的过程中，我们深刻体会到原理图正确不等于实物可用，焊接质量和信号完整性同样关键。

**软件方面**：裸机固件架构虽然简单直接，但在多外设并发（多个 UART 中断 + ADC 采集 + PWM 输出）时需要仔细处理时序。LoRa 通信的可靠性也需要注意——缓冲区大小、JSON 完整性、串口分段接收等问题都需要在代码中妥善处理。Node.js 后端的单文件架构在演示场景下足够简洁，但采样状态机的边界情况（超时、漂移、GPS 丢失）处理花了大量时间调试。

**系统集成方面**：一个完整的物联网系统涉及硬件、嵌入式、通信、后端、前端多个技术领域，任何一个环节的问题都可能导致整条链路不通。我们采用的逐模块验证策略（先 LoRa 通信、再传感器、再电机、最后导航闭环）有效降低了集成风险。

**产品设计方面**：面向真实用户场景（水产养殖户）思考产品功能，而非堆砌技术特性，是本项目的一个重要收获。区域管理、品种配置、风险分析等功能的加入，使系统从一个技术演示升级为有实际使用价值的产品原型。

总体而言，本项目从需求分析到最终实现，团队成员在嵌入式系统设计、无线通信、Web 全栈开发、AI 模型部署等多个技术领域都得到了全面的锻炼和提升。
