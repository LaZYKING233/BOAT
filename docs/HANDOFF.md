## 3. 当前阻塞：船原地打转

### 3.1 现象（2026-11-12 水上实测）

> 原始遥测记录已随仓库保留：`docs/evidence/water1-spin.jsonl`（每行一帧完整 JSON，
> 含 yaw / 航向误差 / 转向输出 / 左右 PWM / GPS / 距离）。
> 可直接用 `node bin/boatctl.js analyze docs/evidence/water1-spin.jsonl` 复查。

```
seq  ns  yaw      误差nt  转向to  左PWM  右PWM   距离
 16   1  174.1   -158.4  -80   -647    999   12.32
 17   1   93.0    -82.3  -80   -647    999   15.20
 18   1 -171.8   -168.6  -80   -647    999   14.42
 32   1 -159.3    178.3  +80    899   -719    9.00
 41   1 -145.6    151.4  +80    899   -719   15.20
```

- 转向输出长期钉在 **±80**（饱和），左右轮一个全速正转、一个全速反转 → 原地自旋
- 航向误差长期在 ±150~180 之间打转，**从不接近 0**
- GPS 全程正常（18~21 颗星），52 秒里船只位移 **8×5.5 米**
- 遥测 2 秒一帧，船转速过快导致**角度混叠**，方向难以直接判读

### 3.2 根因

```c
// 修改前
PID_Init(&heading_pid, 2.0f, 0.35f, 0.25f, 60.0f, 80, 0.7f);
```

`kp = 2.0` 且转向输出上限 `80`：

**航向误差只要超过 40°，转向输出就打满 80。** 船完全丧失比例调节能力——
误差再大也只能给 80，于是全力自旋，2 秒转过头、误差翻到另一侧、再反向给满，
形成极限环。

### 3.3 已完成的修复（**代码已改，未烧录**）

| 参数 | 原值 | 新值 | 理由 |
|---|---|---|---|
| kp | 2.0 | **0.8** | 误差 30°→24、10°→8，全程有比例调节 |
| ki | 0.35 | **0** | 大误差下积分迅速顶到上限，加剧打转 |
| kd | 0.25 | **0.30** | 增加阻尼抑制过冲 |
| 输出上限 | 80 | **45** | 保留转向能力，同时留出"误差变小→转向变小"的空间 |

改动位于 `Hardware/Navigation.c` 的 `Navigation_Init()`，
上限宏 `NAV_HEADING_TURN_LIMIT` 在 `Hardware/Navigation.h`。
提交：`b7c8620`。

> ⚠️ **板子上现在跑的仍然是旧的 kp=2.0 / 上限 80。**

## 4. 唯一还没确定的事：yaw 的方向约定

控制逻辑假设：`航向误差 = 目标方位角 - 当前yaw`，误差为正 → 左轮加速 → 船右转。
这要求 **yaw 顺时针增大**（罗盘约定 0=北、90=东）。

如果模块实际是逆时针增大，船会朝目标的反方向掉头。

**已做的准备**：固件里加了运行时开关（**已烧录并验证可用**）：

```json
{"t":"pid","ys":-1}   // 翻转
{"t":"pid","ys":1}    // 恢复
```

发到网页的「自定义指令」框即可，遥测里的 `ys` 字段能确认是否生效。
**这意味着即使符号错了，也不用捞船重烧。**

**如何判定**（下次下水时，用降低后的增益，转向会很慢，肉眼可辨）：

- 船**朝目标方向转** → 符号正确
- 船**朝目标反方向转** → 发 `{"t":"pid","ys":-1}`，再发一次目标

## 7. 已知陷阱（踩过的坑，别再踩）

### 7.1 串口会"自己断"
USB 重新枚举（搬动设备、USB 省电）会让 WebUI 持有的句柄失效。
**已加自动重连**：掉线后每 2 秒重试，日志打印 `[serial] 自动重连成功`。
三条独立线缆中，**只有 CH340 那条不能拔**。

### 7.2 遥测周期必须 2 秒
LoRa 是半双工共享信道，上行占满空口下行就进不去。实测：

| 遥测周期 | 90 字节下行成功率 |
|---|---|
| 1000ms | **0/3** |
| 1500ms | 3/3 |
| 2000ms | 3/3 |

运行时可用 `{"t":"cmd","cmd":"quiet"}` 静音，`"loud"` 恢复。

### 7.3 newlib-nano 不支持 `%f`
用 `%.3f` 会打印出空字符串。所有浮点遥测字段都用整数编码（×1000 或 ×100）。

### 7.4 电机的静摩擦
低占空比电机不转（起转阈值左 189 / 右 299），但**已经在转的时候可以维持更低转速**。
所以死区补偿必须按"起转阈值"标定，不能按维持阈值。

### 7.5 板子会自己重启
没看门狗、没软件复位调用，实测重启是**供电层面**的（电池插头/搬动）。
重启后果：
- 目标点丢失 → 船停下
- 运行时改的 PID 增益全部丢失 → 回默认
- 电机标定**不会丢**（写在固件默认值里）

### 7.6 GPS 必须开阔天空
室内、阳台都收不到（实测 fix=0、卫星 0）。冷启动要 1~3 分钟。
网上位机里显示的 `sat` 在无信号时可能是乱码（见过 167），只看 `fix` 和经纬度是否合理。

### 7.7 提交时不要包含
`模型/`（SolidWorks 手工作品）、`tools/*.py`（个人脚本），已在 `.gitignore` 里。

## 8. 下一步建议（按顺序）

1. **插 ST-Link 烧录** `b7c8620`，确认遥测里 `hk=800`、`hd=300`、`hi=0`
2. 到**室外开阔处**，等 GPS `fix>0`、卫星数 >5
3. 下水，点地图发一个 **10~15 米**的目标
4. 观察转向方向（增益降低后转速慢，肉眼可辨）
   - 朝目标 → 继续观察能否收敛
   - 背离目标 → `{"t":"pid","ys":-1}`，重发目标
5. 收敛之后，再逐步把 kp 往上调（0.8 → 1.0 → 1.2），每次记录、对比报告
6. 最后再验证"区域保持"（水面原地保持，验证是否会在 6 米内自动回中）
